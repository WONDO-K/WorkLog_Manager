# worklog_manager

각자의 PC에서 실행하는 개인 업무 기록 웹앱입니다. Node.js 24 이상이 필요하며, 내장 SQLite를 사용하므로 SQLite CLI나 외부 패키지를 따로 설치할 필요가 없습니다.

## 실행

1. 이 저장소를 다운로드하거나 복제합니다.
2. 터미널에서 저장소 폴더로 이동한 뒤 `npm start`를 실행합니다. Windows에서는 `start.cmd`를 실행해도 됩니다.
3. 브라우저에서 http://127.0.0.1:8765 를 엽니다.
4. 종료할 때 서버 터미널에서 Ctrl+C를 누릅니다. 서버를 다시 실행하면 저장된 기록을 읽습니다.

`npm install`은 필요하지 않습니다. 기본 DB는 `data/worklog.sqlite`에 생성되고 초기 업무 목록은 비어 있습니다.

## 개인 설정

`config.example.json`을 `config.local.json`으로 복사하고 회사명, DB 경로, 포트를 지정합니다. 상대 경로는 프로그램 폴더 기준이며 기존 SQLite 파일의 절대 경로도 사용할 수 있습니다. 회사명 변경은 데이터 분리를 의미하지 않으므로 다른 업무 DB를 사용하려면 DB 경로도 변경하세요.

개인 설정, DB 및 부속 파일, 내부 기록, 백업, 로그는 Git에서 제외됩니다. 사용자 지정 경로의 민감한 파일도 직접 커밋하지 않도록 주의하세요. 프로그램과 DB는 별개로 백업해야 합니다. 자동 백업은 아직 없습니다.

## 현재 기능

- 요청 등록·제목 및 내용 검색·상태 필터
- 요청 내용, 완료 기준, 고객 납기, 내부 목표일, 다음 행동 수정
- 할 일·진행 중·완료·보류 상태와 시간순 변경 이력
- 완료·보류 전환 시 검증 근거 또는 사유 필수
- 버전 비교로 오래된 화면에서의 덮어쓰기 차단

수정 충돌 시 입력을 복사한 후 최신 기록을 불러와 다시 적용하세요. 날짜는 UTC로 저장하고 화면에는 한국 시간으로 표시합니다. 내부 ID는 UUID, 구조 버전은 SQLite user_version으로 관리합니다.

## 범위

서버는 127.0.0.1에서만 실행합니다. 같은 PC에서 접근 가능한 개인용이며 로그인이나 공동 편집 서버를 제공하지 않습니다. 외부 노출·포트포워딩 용도로 사용하지 마세요.

일일 요약, 외부용 검토·Git 커밋, 자동 백업, Supabase 연결, 대화 자동 수집은 아직 구현하지 않았습니다. 이 프로그램 자체는 Git 명령이나 외부 서비스 호출을 실행하지 않습니다.

## 검증

`npm test`는 임시 DB로 저장·재접속·완료 근거·수정 충돌·접근 제한·설정을 검사합니다. 운영 DB는 테스트하지 않습니다.

## 배포 상태

초기 개발 버전입니다. 라이선스는 저장소 소유자가 공개 배포 전에 결정해야 하며, 현재 오픈소스 라이선스는 부여하지 않았습니다.
